# app

App-wide bootstrap: entrypoint, router wiring, global providers, global styles.
**No business logic. No reusable UI components.** If you're tempted to write a
component here, it belongs in `pages` or `widgets` instead.

## Segments

- `routes/` — TanStack Router's file-based routing root (configured via
  `routesDirectory` in `vite.config.ts`). Route files must stay **thin glue
  only**:
  ```tsx
  // app/routes/index.tsx
  import { createFileRoute } from "@tanstack/react-router";
  import { HomePage } from "@/pages/home";

  export const Route = createFileRoute("/")({ component: HomePage });
  ```
  No inline JSX, no API calls, no business logic in a route file. If a route
  needs data, that belongs in the page/widget it renders, not in the route
  definition. `__root.tsx` is the one exception — it hosts `<AppProviders>`
  and the root `<Outlet />`, because that's literally what "root route" means.
- `providers/` — every app-wide context provider composed in one place
  (`AppProviders`). A new global provider (theme, auth context, etc.) gets
  added here, once, not sprinkled across pages.
- `styles/` — the single Tailwind entry (`@import "tailwindcss"` + `@theme`)
  and any true global CSS.

## Import rules

`app` may import from `pages`, `widgets`, `features`, `entities`, `shared`.
**Nothing may import from `app`** — it's the top of the stack, nothing sits
above it.

## routeTree.gen.ts

Generated by the TanStack Router Vite plugin whenever `dev`/`build` runs.
It's committed to the repo (not gitignored) so a fresh clone type-checks
before anyone has run `vite` once — the plugin overwrites it automatically
as routes change. Never hand-edit it.
